# Plan: RUN-4554 — Deprecate API token auth via URL query parameter

## Context

Security finding PS-1687 (Jira RUN-4554, P3/Low): `SetUserInterceptor.groovy:62` accepts an API
token from the `authtoken` URL query parameter before falling back to the `X-RunDeck-Auth-Token`
header. Tokens in URLs can leak via proxy/CDN/server logs and browser history. The header
mechanism already exists and keeps the token out of the URI.

Approved spec: [.claude/specs/RUN-4554.md](../../.claude/specs/RUN-4554.md). Scope agreed with
user: add a deprecation warning + an opt-out config switch for the *generic* `?authtoken=`
query-param convenience on ordinary API endpoints, defaulting to enabled (no breaking change).
Webhook URLs (`/api/$api_version/webhook/$authtoken`) use `authtoken` as an intentional URL
*path* segment for a different purpose (external systems like GitHub/CI posting without custom
headers) and must be completely unaffected — no warning, no gating. API docs and functional/
integration-level tests are explicitly out of scope per the approved spec.

## Implementation

### 1. `rundeckapp/grails-app/controllers/rundeck/interceptors/SetUserInterceptor.groovy`

Currently (`before()` method):
- Line 62: `def authtoken = params.authtoken? Webhook.cleanAuthToken(params.authtoken) : request.getHeader('X-RunDeck-Auth-Token')`
- Line 83 (inside the `else if (request.api_version && authtoken)` branch): `boolean webhookType = controllerName == "webhook" && actionName == "post"`

`webhookType` only depends on `controllerName`/`actionName`, which are available regardless of
`authtoken`, so it can be computed earlier without side effects. Reorder and gate:

```groovy
// webhookType must be known before extracting authtoken: webhook URLs carry the token as a
// path segment by design and must never be warned about or gated by the query-param switch below.
boolean webhookType = controllerName == "webhook" && actionName == "post"

def authtoken
if (params.authtoken) {
    if (webhookType || configurationService.getBoolean("security.apiTokenQueryParamAuth.enabled", true)) {
        authtoken = Webhook.cleanAuthToken(params.authtoken)
        if (!webhookType) {
            log.warn("API token authentication via URL query parameter (authtoken) is deprecated and may be removed in a future release; use the X-RunDeck-Auth-Token header instead. Token: ${AuthenticationTokenUtils.printable(authtoken)}")
        }
    } else {
        authtoken = request.getHeader('X-RunDeck-Auth-Token')
    }
} else {
    authtoken = request.getHeader('X-RunDeck-Auth-Token')
}
```

Then remove the now-duplicate `boolean webhookType = ...` declaration at the old line 83 and
use the variable computed above in the existing `lookupToken(authtoken, servletContext, webhookType)`
call. No other lines in `before()` change — everything downstream keys off the local `authtoken`
variable exactly as today.

`AuthenticationTokenUtils.printable()` and `Webhook.cleanAuthToken()` are already imported in
this file (used elsewhere for invalid-token logging / fragment stripping) — no new imports
needed. Config flag name/default follow the file's own existing local convention
(`security.apiCookieAccess.enabled` at line 57, `security.authorization.preauthenticated.enabled`
at lines 73/79): `security.<feature>.enabled` boolean via `configurationService.getBoolean(...)`.

### 2. `rundeckapp/src/test/groovy/rundeck/interceptors/SetUserInterceptorSpec.groovy`

**Fix existing test** — `"skip requiredRoles check if the call is performed by the runner"`
(currently ~line 331) sets `interceptor.params.authtoken = "123"` on a non-webhook route with
`configurationService` mocked but no `getBoolean` stub. Once the new code path calls
`configurationService.getBoolean("security.apiTokenQueryParamAuth.enabled", true)`, Spock's
unstubbed-mock default (`false` for a primitive boolean return) would flip this to "disabled",
breaking the test. Add `getBoolean(_,_) >> true` to that test's `Mock(ConfigurationService) {...}`
block to preserve current behavior.

**Add three new tests**, modeled on the existing `"api token request authenticates even if
session user is already set"` test (~line 293) for setup style:

1. *Query-param auth enabled (default) still authenticates and logs a deprecation warning* —
   non-webhook route, `params.authtoken` set to a valid token, `configurationService` mock
   returns `getBoolean(_,_) >> true`. Assert authentication succeeds as today (`request.authenticatedUser`,
   `session.user`), and assert the warning was logged using the existing in-repo precedent for
   capturing `log.warn` output — the Log4j2 `WriterAppender` pattern already used in
   `rundeckapp/src/test/groovy/rundeck/services/events/UserActionServiceSpec.groovy` (lines 35-64):
   attach a `WriterAppender` to the root logger context at `Level.WARN` in `setup:`, assert the
   captured text mentions the deprecation, remove the appender in `cleanup:`.
2. *Query-param auth disabled ignores the query param, falls back to header behavior* —
   non-webhook route, `params.authtoken` set, no `X-RunDeck-Auth-Token` header,
   `configurationService` mock returns `getBoolean(_,_) >> false`. Assert no exception is thrown
   and the request ends up unauthenticated (`request.invalidApiAuthentication` true / no
   `authenticatedUser`) — identical outcome to "no authtoken sent at all" today.
3. *Webhook requests are unaffected regardless of the flag* — set up the request as a webhook
   route (`controller: "webhook", action: "post"`, matching the existing `withRequest(controller:
   ...)` helper used elsewhere in this spec, e.g. line 45), `params.authtoken` set to a valid
   token, `configurationService` mock returns `getBoolean(_,_) >> false` (i.e. the switch would
   disable the generic mechanism). Assert authentication still succeeds via the token and no
   deprecation warning is logged.
