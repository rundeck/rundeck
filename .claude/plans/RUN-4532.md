# Plan: RUN-4532 - Postinstall encryption password entropy fix

## Context

RUN-4532 is a security finding (PS-1681) against Rundeck's RPM/DEB packages: the shipped
config template hardcodes `default.encryption.password` for both storage converters, and
the postinstall scripts that are supposed to randomize it only use 64 bits of entropy
(`openssl rand -hex 8`), and on DEB the randomization is wrapped in a conditional that RPM
doesn't have. Spec (`.claude/specs/RUN-4532.md`) scopes this PR to the code fix only:
bump entropy to 128 bits, make DEB unconditional like RPM, and add test coverage — no
audit/rotation of live instances, no docs, no splitting the two converters into separate
passwords.

## Changes

### 1. `packaging/lib/rpm/scripts/postinst.sh` (lines 52-55)
Change line 53 from:
```sh
STORAGE_PASS=$(openssl rand -hex 8)
```
to:
```sh
STORAGE_PASS=$(openssl rand -hex 16)
```
No other change here — this block is already unconditional.

### 2. `packaging/lib/deb/scripts/postinst` (lines 93-98)
Currently:
```sh
#setting a random password for encryption
if [ -f "$DIR/rundeck-config.properties" ] ; then
  STORAGE_PASS=$(openssl rand -hex 8)
  sed -i -E 's/^rundeck\.storage\.converter\.([0-9]+)\.config\.password=default\.encryption\.password$/rundeck.storage.converter.\1.config.password='"$STORAGE_PASS"'/' "$DIR/rundeck-config.properties"
  sed -i -E 's/^rundeck\.config\.storage\.converter\.([0-9]+)\.config\.password=default\.encryption\.password$/rundeck.config.storage.converter.\1.config.password='"$STORAGE_PASS"'/' "$DIR/rundeck-config.properties"
fi
```
Change to (drop the `if` guard, bump entropy, keep the two sed lines and `$DIR/rundeck-config.properties` target as-is):
```sh
#setting a random password for encryption
STORAGE_PASS=$(openssl rand -hex 16)
sed -i -E 's/^rundeck\.storage\.converter\.([0-9]+)\.config\.password=default\.encryption\.password$/rundeck.storage.converter.\1.config.password='"$STORAGE_PASS"'/' "$DIR/rundeck-config.properties"
sed -i -E 's/^rundeck\.config\.storage\.converter\.([0-9]+)\.config\.password=default\.encryption\.password$/rundeck.config.storage.converter.\1.config.password='"$STORAGE_PASS"'/' "$DIR/rundeck-config.properties"
```
The `sed` patterns are unchanged — they still only match a line whose value is literally
`default.encryption.password`, so an already-randomized config on upgrade is still a no-op.
`set -e` is active at the top of this script, so if `$DIR/rundeck-config.properties`
genuinely doesn't exist the `sed` calls will fail the postinstall the same way any other
missing-file `sed` in this script already would — consistent with how RPM's equivalent
block behaves (no guard there either).

### 3. `packaging/test/docker/installcommon/scripts/deb-tests.sh` and `rpm-tests.sh`
Both currently define `test_status`, `test_start_twice`, `test_all` only. Add a new
`test_encryption_password` function (identical in both files, matching the existing
`echo "..."` / `grep` / `{ echo "FAILED" ; exit 2 ; }` style already used by `test_status`)
and call it from `test_all`. Confirmed from `rd-util.sh`'s `echo_config()` that the config
lives at the fixed path `/etc/rundeck/rundeck-config.properties` inside the test container
regardless of package type, so the same check works in both files:

```sh
test_encryption_password(){
	echo "test_encryption_password"
	local CONFIG=/etc/rundeck/rundeck-config.properties
	grep -q 'default\.encryption\.password' "$CONFIG" && { echo "FAILED" ; exit 2 ; }
	local PASS
	PASS=$(grep -E '^rundeck\.storage\.converter\.[0-9]+\.config\.password=' "$CONFIG" | head -1 | cut -d= -f2)
	echo "$PASS" | grep -qE '^[0-9a-f]{32}$' || { echo "FAILED" ; exit 2 ; }
	echo "OK"
}
```
and add `test_encryption_password` as a new line inside `test_all()` in both files.

## Out of scope (per spec)
No changes to `packaging/lib/common/etc/rundeck/rundeck-config.properties`, RPM's
`.rpmnew` resolution logic, splitting the two converters into independent passwords, or
any docs.
