# SPEC: RUN-4832 - Enforce file resource-model path containment in core node loading

## Objective
Prevent core node-loading consumers from reading file resource-model sources outside a project's directory unless the canonical path is explicitly covered by the configured allowed base paths.

## Acceptance Criteria
- [ ] Every `file` resource-model source is path-validated in the shared core node-loading pipeline before its nodes can be returned to callers such as the Nodes page, resource API, node-tag lookup, or job dispatch -- Verification: integration test
- [ ] A file source whose canonical path is within the owning project's directory loads normally -- Verification: unit test
- [ ] A file source outside the project directory loads only when its canonical path is within a base path configured by `rundeck.resourceModelSource.file.allowedBasePaths` -- Verification: unit test
- [ ] A file source outside both the project directory and all configured allowed base paths is rejected at load time, including sources previously configured by an administrator -- Verification: integration test
- [ ] Path containment uses canonical/real path semantics so `..` traversal and symlink traversal cannot escape a permitted directory -- Verification: unit test
- [ ] The existing `rundeck-config.properties` allowed-base-path setting is made available to the core loading path without requiring duplicate configuration in `framework.properties` or coupling core code to Grails -- Verification: unit test
- [ ] Rejection errors do not expose the disallowed filesystem path, and existing FrameworkController save/read/write validation remains in place as defense in depth -- Verification: unit test
- [ ] Non-file resource-model source types continue to load without file-path containment validation -- Verification: unit test

## Scope
- **In scope:**
  - Enforcing file source path containment at the shared `ProjectNodeSupport` node-loading chokepoint.
  - Plumbing the framework/project context and the resolved `rundeck.resourceModelSource.file.allowedBasePaths` value into core through both `ProjectNodeSupport` construction paths.
  - Canonical path checks covering traversal and symlink escapes.
  - Unit tests for containment, allowlisting, safe errors, and unaffected source types.
  - Integration coverage proving a disallowed source cannot expose parsed node data through a node-loading consumer.
- **Out of scope:**
  - An administrator bypass, opt-in flag, or warn-only rollout mode.
  - Automatically migrating existing cross-project file source configurations; administrators must add legitimate locations to `allowedBasePaths`.
  - Removing the existing FrameworkController validation.
  - Expanding access to raw file bytes or credentials.
  - Separate save-time validation changes to `saveProjectPluginsAjax` beyond the core load-time enforcement required by this ticket.
