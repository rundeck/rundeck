# SPEC: RUN-4532 - Remediate Hardcoded Default Encryption Password in Rundeck Package Installs

## Objective
Increase the entropy of the randomly-generated encryption password set by the RPM/DEB postinstall scripts from 64 bits to 128 bits, and make DEB's randomization step unconditional to match RPM, so package installs no longer risk shipping with a low-entropy or (on skipped postinst) default key-storage password.

## Approach
Apply the same two-line fix independently to both `packaging/lib/rpm/scripts/postinst.sh` and `packaging/lib/deb/scripts/postinst` (they share no common library, so each must be edited separately):

1. Change `openssl rand -hex 8` (64 bits) to `openssl rand -hex 16` (128 bits) in both scripts. The existing `sed` substitutions already only match lines still set to the literal `default.encryption.password`, so this preserves idempotency on upgrade (an already-randomized line is never touched again) without any further change.
2. Remove the `if [ -f "$DIR/rundeck-config.properties" ]` guard in the DEB script so password randomization always runs, matching RPM's unconditional behavior. dpkg guarantees the config file is unpacked before `postinst` runs, so this does not change observed behavior on a normal install/upgrade — it only removes a redundant conditional.
3. Extend the existing Docker-based install-test harness (`packaging/test/docker/installcommon/scripts/deb-tests.sh` and `rpm-tests.sh`) with assertions that, after install, `rundeck-config.properties` no longer contains the literal string `default.encryption.password` and that the substituted password value is 32 hex characters (128 bits).

Explicitly not changed (confirmed out of scope during clarification): splitting the two storage converters (`rundeck.storage.converter.1` / `rundeck.config.storage.converter.1`) into independently-generated passwords — they will continue to share one generated `$STORAGE_PASS`/equivalent value, only its entropy changes. RPM's `.rpmnew` upgrade-file handling is untouched. No provisioning/documentation changes.

## Acceptance Criteria

- [ ] `packaging/lib/rpm/scripts/postinst.sh` generates the storage-converter password with `openssl rand -hex 16` instead of `-hex 8` -- Verification: manual
- [ ] `packaging/lib/deb/scripts/postinst` generates the storage-converter password with `openssl rand -hex 16` instead of `-hex 8` -- Verification: manual
- [ ] `packaging/lib/deb/scripts/postinst` runs password randomization unconditionally (the `if [ -f "$DIR/rundeck-config.properties" ]` guard around that block is removed) -- Verification: manual
- [ ] Both sed substitutions still only replace lines whose value is exactly `default.encryption.password`, leaving an already-randomized password untouched on upgrade (no regression to idempotency) -- Verification: manual
- [ ] `packaging/test/docker/installcommon/scripts/deb-tests.sh` asserts, after install, that `rundeck-config.properties` does not contain `default.encryption.password` and that the substituted password is a 32-character hex string -- Verification: script
- [ ] `packaging/test/docker/installcommon/scripts/rpm-tests.sh` asserts the same two conditions for the RPM install -- Verification: script

## Scope
- **In scope:** Entropy fix (hex 8 -> hex 16) and DEB unconditional-guard removal in the two postinst scripts; adding install-test assertions for the fixed behavior.
- **Out of scope:** Auditing/rotating secrets on already-deployed instances (ticket items 1-2, ops action, not a code change); provisioning/documentation hardening guidance (ticket item 3); splitting the two storage converters into independently-generated passwords; any change to RPM's `.rpmnew` upgrade-file resolution logic; Docker/WAR install paths (already unaffected, confirmed in exploration).

## Context
- Jira ticket: RUN-4532 (source security report: PS-1681)
- Related tickets: PS-1681 (Public Security Report, source of this finding)
- Relevant files:
  - `packaging/lib/rpm/scripts/postinst.sh` (lines ~52-55: unconditional password randomization, `openssl rand -hex 8`)
  - `packaging/lib/deb/scripts/postinst` (lines ~93-98: guarded password randomization, `openssl rand -hex 8`)
  - `packaging/lib/common/etc/rundeck/rundeck-config.properties` (shared template containing the two `default.encryption.password` lines both scripts target)
  - `packaging/test/docker/installcommon/scripts/deb-tests.sh`, `rpm-tests.sh` (existing install-test harness to extend; currently only checks `service rundeckd status`)
- Existing patterns: Both postinst scripts use a `sed -E` substitution keyed on the literal default value, which is what keeps re-running postinst on upgrade a no-op once the password has been randomized -- this pattern must be preserved, not replaced. `RundeckInitializer.groovy` (WAR/launcher install path, out of scope here) already generates a 15-character random string for the same purpose and is unaffected by this change; it's a useful reference showing the WAR path was never vulnerable to this issue. Docker's `remco` config template injects the password from operator-supplied values with no hardcoded default, also unaffected.
